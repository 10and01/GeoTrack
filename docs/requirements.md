# GeoTrack 需求规约

## 目标

面向课程答辩构建一个可运行的 GPS 轨迹大数据 Web 应用，完成轨迹清洗、停留点提取、热点区域挖掘、用户时段模式分析以及地图/图表交互展示。

## 用户角色与场景

- 分析者：查看数据规模、质量、热点与用户模式。
- 演示者：通过用户、时间和空间筛选展示一条轨迹或一个热点。
- 批处理管理员：触发导入/挖掘任务并查询任务状态。

## 功能需求

1. 支持 GeoLife PLT 解析、字段标准化和数据质量统计。
2. 支持轨迹摘要、点详情和空间范围查询。
3. 支持 200m/20min 默认停留点提取。
4. 支持 eps=500m、minPts=3 演示参数的 DBSCAN 热点分析。
5. 支持用户时段特征聚类和 24 小时分布可视化。
6. 支持数据总览、轨迹探索、热点分析、模式分析和任务质量页面。
7. 所有重计算通过后台任务接口触发，不阻塞查询请求。

## 非功能需求

- 原始数据不提交 Git；README 提供合规说明和本地路径配置。
- API 查询默认基于预计算结果；演示子集查询目标响应时间不超过 3 秒。
- 前端具备加载、空数据、错误和窄屏状态。
- 代码、规约、提示词、报告、视频和 PPT 可独立提交。

## 验收指标

- 解析器通过 PLT 文件头、GMT 时间、非法点、重复点和断点测试。
- Spark/本地批处理可重复生成 `data/processed/demo.json`。
- DBSCAN 能在测试数据中发现两个已知热点。
- API 与前端能够完成筛选、地图点击、图表联动和任务状态展示。
